## eDrawings 横断面按钮程序化调用
- 结论：eDrawings 标准 API（IEModelViewControl / Interop.EModelView.dll）**没有**暴露 Section/剖切方法（2010~2027 各版本成员列表均无 SetSection）。必须驱动内部工具栏按钮。
- 方案：Win32 工具栏消息——找到 eDrawings 的 ToolbarWindow32 子窗口，取 Section 按钮 idCommand，向主窗口 PostMessage(WM_COMMAND, idCommand)。命令 ID 跨版本基本稳定。
- 备选：UI Automation 按名称 Invoke（原生 MFC 工具栏常不暴露 UIA，仅作 fallback）。
- 交付：新建 `eDrawingsChecker/EDrawingsSectionInvoker.cs`，含 TryFindSectionButton / InvokeSectionById / DumpToolbarButtons（诊断打印所有按钮序号-idCommand-文字，用于对照钩子捕获的 idCommand）/ InvokeSectionViaUIA。
- 注意点：用户已用钩子捕获按钮信息；建议先跑 DumpToolbarButtons 对照 idCommand，再固定用 InvokeSectionById。程序与 eDrawings 需同位数、同提权级别。

## 修正：工程其实是 VB.NET（非 C#）
- 工程 `eDrawingsChecker` 为 VB.NET WinForms，x64 / .NET 4.8，类名为 `eDrawingsChecker`，已承载两个控件 `AxEModelViewControl1`(右) 与 `AxEModelViewControl2`(左)，按钮用 `Handles xxx.Click` 接（如 btn_measure）。
- 已把驱动代码改写为 `EDrawingsChecker/EDrawingsSectionInvoker.vb`（Module，命名空间 eDrawingsChecker），并加入 .vbproj 的 Compile，删除原 .cs。
- **关键修正**：eDrawings 是嵌在 AxHost 内的 ActiveX，WM_COMMAND 必须发给 eDrawings 内部命令窗口（工具栏父链顶端，即父链中父=AxHost 的那个窗口），不能发给整个 Form，否则消息到不了 eDrawings。已实现 GetCommandTarget() 回溯父链。
- 已加 `InvokeSectionById(root, idCommand)` 重载（内部自动定位工具栏），适配"已知命令 ID（来自钩子）"的最稳场景。
- 用 Framework vbc 实测编译通过（修正：.NET 4.8 的 String.Replace 无 3 参重载；旧 vbc 不认 $"" 插值，已全部改 String.Format）。
- 用法：文档加载后调用 `EDrawingsSectionInvoker.InvokeSection(AxEModelViewControl2.Handle)`；或先用 `DumpToolbarButtons` 在 VS 输出窗口定位真实 idCommand，再固定用 `InvokeSectionById(root, id)`。需确保 FullUI=True 且文档已加载（工具栏才存在）。

## 重要发现：横断面入口其实是 class=Static 的控件（不是 ToolbarWindow32 按钮）
- 用户运行诊断后报告关键行：`[Win] hwnd=0x119B8 class=Static text="插入横断面"` —— 即 eDrawings 的“插入横断面”是个 `Static` 控件（文字即命令名），**没有工具栏 idCommand**。因此之前只按工具栏按钮的思路需扩展。
- 已升级 `EDrawingsSectionInvoker.vb`：
  - `SectionHit` 增加字段 Hwnd / Kind / ControlId / ParentHwnd / FrameHwnd / MenuId。
  - `Walk()` 不仅对工具栏按钮、也对**任意文字命中关键字的窗口**（含 Static）记录命中；并 `GetWindowLong(GWL_ID)` 取控件 ID、`GetParent` 取父窗口、`GetTopAncestor` 取拥有菜单的 frame、并用 `FindMenuCommandId` 递归搜索该控件所有祖先窗口的菜单，尝试解析出**菜单项 ID（MenuId）**。
  - `InvokeFoundSection(index)` 自动优选：`MenuId>0` → `PostMessage(Frame, WM_COMMAND, MenuId)`（最干净：无需坐标、不抢焦点）；`Kind=Toolbar` → 工具栏命令；否则 `ClickWindow(hwnd)` 用 `SetCursorPos`+`mouse_event` **模拟真实鼠标点击该控件中心**（对 Static 最可靠，等价于用户点击）。
  - 新增 `ClickWindow(hWnd)` 公共方法（模拟点击）。新增 P/Invoke：`GetWindowLong/GetWindowRect/SetCursorPos/mouse_event/GetMenu/GetSubMenu/GetMenuItemCount/GetMenuItemInfo/GetMenuString` 及 RECT、MENUITEMINFO 结构。
- `main.vb` 诊断摘要与“触发”按钮改为显示更丰富信息（Class/hwnd/CtrlId/Parent/MenuId），并提示实际调用的方式（菜单命令/工具栏/鼠标点击）。
- 编译校验（Framework vbc + 真实 interop）：除用户原有 `$""` 插值行与类库 `End` 语句（VS/Roslyn 支持、旧 vbc 不支持）外，新增代码零错误。
- 用户重跑诊断，确认两个稳定控件 ID（左右控件一致）：`插入横断面` = Static, **CtrlId=1094**；`横断面平面选择` = Button, **CtrlId=1042**。菜单解析未拿到 MenuId（走 Else 分支），故采用模拟鼠标点击。

## 关键修正：两步法 + 修复诊断“触发”的 index 错选（用户报“点了没反应/鼠标变了”）
- 关键认知：eDrawings 的“插入横断面”是**两步操作**——点按钮仅进入“剖切平面点选”模式，必须在 3D 视口里**再点一下**才真正生成剖切。用户之前“鼠标位置变了但无剖切”= 第 1 步触发成功（鼠标被模拟点击移动 / 进入点选模式），缺第 2 步视口点击。
- 工具栏里“插入横断面”图标按钮（空文字）的命令 ID = **32783**（用户从 DumpToolbarButtons 发现）。已固化为常量 `SECTION_TOOLBAR_CMD = 32783`。
- 修复 bug：诊断窗体“触发横断面”原用 `FoundSections(0)`，但 `[0]` 是“横断面平面选择”(1042) 而非“插入横断面”，导致触发错按钮。改为 `FindInsertSectionHitIndex()` 优先选文字含“插入横断面”的入口。
- 模块新增/改写：
  - `InvokeInsertSection(root)` 改为两步：先 `ClickWindow(1094 Static)` 入模式，Sleep(200) 后 `ClickWindow(root)` 在视口中心放置剖切平面。
  - 新增 `InvokeInsertSectionByCmd(root, cmd)`：用 `WM_COMMAND(cmd)`（不移动鼠标）入模式 + 视口点击；找不到工具栏返回 False。
  - 新增 `FindInsertSectionHitIndex()`。
- `main.vb`：
  - `btnInsertSection_Click` 改为两步法，优先 `InvokeInsertSectionByCmd(root, 32783)`，失败回退 `InvokeInsertSection(root)`。
  - `btnDiagTrigger_Click` 用 `FindInsertSectionHitIndex()` 选对入口；触发后若为“插入横断面”再在视口点击放置平面。
- 编译校验：新增/改动代码在 Framework vbc + 真实 interop 下零错误（仅用户原 `$""` 与 `End` 这俩旧 vbc 不支持的项）。
- 待用户验证：点“横断面”按钮（两步法）后 eDrawings 视图是否出现剖切；若 32783 仍无反应则回退路径(1094)应工作。
