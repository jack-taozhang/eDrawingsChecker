## 修复：Previous/Next 加载后左侧面板未自动收纳（00:44）
- 现象：首次“Open”能收，但 Previous/Next 切换后左侧面板不收。两者都走 `LoadCurrentFile()`，代码路径相同 → 根因是**时序**。

- 修复：把自动收纳从 `LoadCurrentFile()` 移到 `AxEModelViewControl2_OnFinishedLoadingDocument`（文档真正加载完成后触发）。为避免加载瞬间面板未稳定，用 `System.Windows.Forms.Timer`（350ms）延迟一拍再 `SetEDrawingsLeftPanel(AxEModelViewControl2.Handle, True)`。定时器在 `eDrawingsChecker_Load` 中创建并挂 `CollapseTimer_Tick`。
- 效果：首次 Open、Previous、Next 三种路径都经 `OnFinishedLoadingDocument` → 加载完面板展开并稳定 → 定时器触发收纳，统一且确定性生效。

## 修复：打开模型报 IllegalCrossThreadCall（00:47）
- 报错：`InvalidOperationException: IllegalCrossThreadCall`（跨线程访问控件）。
- 根因：**eDrawings 的 `OnFinishedLoadingDocument` 事件在 eDrawings 自己的后台线程回调**，不在 UI 线程。上一版把自动收纳挪到这里并 `collapseTimer.Start()`；若从后台线程启动 `System.Windows.Forms.Timer`，其 `Tick` 也在后台线程触发，于是 `SetEDrawingsLeftPanel(AxEModelViewControl2.Handle, ...)` 读取控件句柄时抛跨线程异常。原先的 `ViewOperator=` 是 COM 赋值不触发该检查，所以之前没暴露。
- 修复：事件入口加 `If Me.InvokeRequired Then Me.BeginInvoke(AddressOf ..., sender, e) : Return`，把整个后续逻辑（设 `ViewOperator`、启动定时器）切回 UI 线程执行；定时器在 UI 线程启动，Tick 自然在 UI 线程，`AxEModelViewControl2.Handle` 访问安全。
- 项目约定（重要）：**所有 eDrawings ActiveX 事件回调（OnFinishedLoadingDocument 等）都默认在后台线程触发，凡涉及本程序控件/句柄/UI 的操作必须先 `InvokeRequired → BeginInvoke` 切回 UI 线程。**
- 编译校验：新增代码零错误。

## 编译错误修复（00:50）
- 错误1 `883 AddressOf 无法转换为 [Delegate]（MustInherit）`：`Control.BeginInvoke` 首参是抽象 `Delegate`，`AddressOf` 不能直接转。改为显式构造具体委托：
  `Me.BeginInvoke(New Action(Of Object, AxEModelView._IEModelViewControlEvents_OnFinishedLoadingDocumentEvent)(AddressOf AxEModelViewControl2_OnFinishedLoadingDocument), sender, e)`。
- 错误2 一堆 `XML 文档分析错误`：全部源于 `EDrawingsSectionInvoker.vb:430` 的 `''' <summary>…（收纳 <-> 展开）…</summary>` 里字面 `<->`——XML 文档注释把 `<` 当标签开头、`-` 当非法标签名首字符，导致其后所有注释级联报错。把 `<->` 改成 Unicode `↔` 即可（其余 `<summary>`/`<remarks>` 均合法）。
- 经验：VB 里跨线程回 UI 用 `BeginInvoke` 必须传**具体委托类型**；`'''` 文档注释内严禁出现裸 `<`（用 `↔` 或 `&lt;`/`&gt;` 转义）。

## 修复：切换模型左侧面板仍不收纳（01:00 排查）
- 用户实测：Previous/Next 切换后左侧面板**仍未**自动收纳（之前两版都依赖 `OnFinishedLoadingDocument`）。
- 最新研判根因：**eDrawings 在“切换（重新 OpenDoc）文档”时，`OnFinishedLoadingDocument` 事件未必会再次触发**（很多版本只首发触发一次），于是定时器从未启动 → 什么都不做。
- 修复思路：不再依赖该事件作为唯一触发，改为**“时间窗口轮询”**：
  1. 新增 `EnsureLeftPanelCollapsed(root)`（EDrawingsSectionInvoker）：找到面板后**仅当展开才点击**，已收纳/未找到则不操作 → 绝不把已收起的面板误点开。
  2. `LoadCurrentFile()` 在 `OpenDoc` 之后立即 `ScheduleAutoCollapse()`（UI 线程启动，不依赖事件）；`OnFinishedLoadingDocument`（若触发）也调用它刷新窗口。
  3. `ScheduleAutoCollapse()`：设 8 秒时间窗口、启动 `collapseTimer`（500ms 一拍）。
  4. `CollapseTimer_Tick`：窗口内每拍调 `EnsureLeftPanelCollapsed`；展开→点击收纳、已收纳/未找到→等下一拍；到窗口结束停止。
  - 这样：无论事件是否触发，切换文件都会进入轮询；面板加载完若被 eDrawings 重新展开则会被收纳；若 eDrawings 记住收起态则本就收着（一致结果）；也规避了“上一文档仍是收起态瞬间误判已收”的漏点。
- 诊断：用 `LogHook` 把每拍状态（`[AutoCollapse] 未找到面板/已收纳/已点击收纳` + 窗口开关）写入 `%TEMP%/eDrawingsChecker_hook.log`，用户可直接看日志定位到底是“事件没触发 / 面板没找到 / 找到但没点到”。
- 编译校验：新增代码零错误（无 `$"..."`/`End`，Timer 仍用 `System.Windows.Forms.Timer` 完全限定）。
- 待用户验证：构建后连点 Previous/Next，看日志是否出现“已点击收纳”且面板最终收起；若仍展开且日志全是“未找到面板”，说明面板 class/句柄探测需再调。

## “内存不足”报错根因与修复（10:30）
- 用户报 `throw SafeNativeMethods.Gdip.StatusException(num); System.OutOfMemoryException:"内存不足。"`（多次出现）。

## 修复“内存不足”（OutOfMemoryException）（10:18）
- 用户反馈：这么小的软件已多次报内存不足。逐项排查后锁定根因，并排除若干常见嫌疑：
  - **排除**：全局鼠标钩子（`SetWindowsHookEx` 仅在 `eDrawingsChecker_Load` 装一次、`FormClosed` 卸一次，非泄漏）；GDI 对象（全文件无 `New Bitmap/CreateGraphics/New Font/New Icon`）；事件订阅（仅 2 处 `AddHandler`，均为一次性）；日志（`File.AppendAllText`，无句柄泄漏）。
  - **根因**：eDrawings 是**非托管 ActiveX**，模型/图纸数据全在非托管堆；.NET 侧只持有极小的 RCW 包装对象 → **GC 感知不到压力、不会自动回收** → 每切换一个模型就把上一个模型的内存继续攒着，累积到 OOM。这是典型的"托管堆很小、非托管堆巨大"问题。
- 修复（`main.vb`）：
  - 新增 `ReleaseEDrawingsMemory()`：`GC.Collect()` → `GC.WaitForPendingFinalizers()` → `GC.Collect()`；用 `Using` 包住 `Process.GetCurrentProcess()` 以免自身泄漏句柄；前后各取一次 `WorkingSet64` 并通过 `LogHook` 输出 `内存回收：X MB → Y MB`，便于验证效果。
  - `LoadCurrentFile()` 在两个 `CloseActiveDoc("")` 之后、打开新文档之前调用它。
- 验证方式：切换模型时看 `E:\Temp\eDrawingsChecker_hook.log` 里的 `内存回收：XMB → YMB`；若切换多次后数值不再单调增长（回收后能降回去），说明修复生效。
- 遗留观察（未改，需用户决策）：程序**同时**用两个 eDrawings 控件实例分别加载模型与其工程图，内存约翻倍。大装配体若仍吃紧，可考虑改为按需/延迟加载工程图视图。
